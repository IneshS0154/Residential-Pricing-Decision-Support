# Preprocessing Decision Log

Generated by `notebooks/02_preprocessing.ipynb` (section 18). Evidence IDs refer to `docs/eda_insight_log.md`.

## Structural missing values (14 columns)
- **Problem Identified:** 'NA' means the facility does not exist; most-frequent fill would assign facilities that are not there
- **Methods Considered:** Most-frequent value; "Unknown" category; verified NoFeature
- **Selected Method:** NoFeature when related columns confirm absence; facility-conditional mode when the facility exists
- **Justification:** Each NA is tied to a verified zero (garage, basement, fireplace, pool, misc) or to documentation (alley, fence)
- **Evidence:** Garage, basement, fireplace, pool and misc: every confirmed NA matches a zero; contradictions are Ids 333 and 949 in train and 14 group-level cases in test (2 garage, 8 basement, 3 pool, 1 misc) [F05]
- **Limitations:** Alley and Fence cannot be cross-checked; absence taken from data_description.txt

## Numerical missing values
- **Problem Identified:** Zero-filling unknown measurements would invent absent facilities; mean is distorted by skew
- **Methods Considered:** Zero; mean; median
- **Selected Method:** Zero only for verified absence (Case A); median for unknown values (Case B)
- **Justification:** Median of MasVnrArea is 0 while its mean is 103.7 sq ft; LotArea skew 12.2
- **Evidence:** GarageArea has no NaN in train; Case B occurs in test (Id 2577) [F06, F09]
- **Limitations:** Median ignores relationships with other columns

## Categorical mode imputation
- **Problem Identified:** A few genuinely missing categories (Electrical 1, MasVnrType 8; more in test)
- **Methods Considered:** Mode; "Unknown" category
- **Selected Method:** Most frequent category (SimpleImputer)
- **Justification:** Every house built since 2000 has SBrkr, and Id 1380 was built in 2006; an Unknown level would hold 1 training row and be pooled by min_frequency
- **Evidence:** Electrical SBrkr 91% [F06]
- **Limitations:** The imputed value is an assumption, not the true category

## LotFrontage: neighborhood median
- **Problem Identified:** 17.7% missing, not missing at random
- **Methods Considered:** Global median; neighborhood median
- **Selected Method:** Both implemented and tested; see comparison
- **Justification:** Hidden-value recovery RMSE: global 24.1 ft, neighborhood 22.1 ft
- **Evidence:** Missingness tied to LotShape, Neighborhood, LotConfig [F07]
- **Limitations:** Neighborhoods with few observed values give noisy medians

## LotFrontage: KNN
- **Problem Identified:** Use property similarity rather than location only
- **Methods Considered:** KNN with k = 3, 5, 7; scaled / unscaled; core / extended features
- **Selected Method:** Compared with the median methods
- **Justification:** Best KNN recovery RMSE 19.0 ft (KNN k=5, scaled, extended features); reference ratio method 19.4 ft
- **Evidence:** See section 8
- **Limitations:** Depends on feature choice, k and scaling; not automatically better

## Missing-indicator feature
- **Problem Identified:** Imputed and measured frontages look identical afterwards
- **Methods Considered:** No indicator; LotFrontage_Missing
- **Selected Method:** Compared; adopted only if it improves cross-validated error
- **Justification:** Paired RMSE difference with vs without indicator: -0.00001
- **Evidence:** Missing share 52% on cul-de-sacs vs 13% inside [F07]
- **Limitations:** Adds a column for little information if the difference is within noise

## Categorical encoding
- **Problem Identified:** Arbitrary integer codes would impose an order
- **Methods Considered:** Label encoding; one-hot; ordinal; target encoding
- **Selected Method:** Ordinal for rating scales, one-hot (min_frequency = 10) for nominals, MSSubClass as nominal
- **Justification:** MSSubClass code has no monotone relation with price; rating scales have a natural order
- **Evidence:** Neighborhoods with 2-9 sales; unseen MSSubClass 150 in test [F12, F24]
- **Limitations:** Ordinal vs one-hot for the rating scales was not compared experimentally; target encoding of Neighborhood not tested (decision D3 open)

## Outliers
- **Problem Identified:** Extreme sizes could distort fits
- **Methods Considered:** Remove; cap; transform; keep
- **Selected Method:** Keep all rows in the pipeline; log1p for skewed columns; optional exclusion of Ids 524 and 1299 left as a group decision
- **Justification:** Ids 524 and 1299 are unfinished (Partial) sales priced far below their size; effect on Ridge CV RMSE of dropping them from training: -0.00416 (SE 0.00100)
- **Evidence:** EDA F17, F18
- **Limitations:** Exclusion rests on out-of-model knowledge of the sale type (decision D2 open)

## Feature scaling
- **Problem Identified:** Mixed units; Ridge and KNN depend on magnitude
- **Methods Considered:** None; StandardScaler; RobustScaler
- **Selected Method:** RobustScaler (paired RMSE gain over StandardScaler 0.00060, SE 0.00026); scale=None for trees
- **Justification:** RMSE: standard 0.1315, robust 0.1309, none 0.1335
- **Evidence:** Skewed areas [F10]
- **Limitations:** Compared with a single fixed Ridge strength

## Feature engineering
- **Problem Identified:** Related columns describe one attribute; years conflict with the unknown sale year
- **Methods Considered:** Raw columns; derived totals and ages
- **Selected Method:** TotalSF, TotalBathrooms, HouseAge, RemodAge, IsRemodeled (reference year 2010)
- **Justification:** Derived features carry the same information in one interpretable column; no sale-context variable is used
- **Evidence:** Collinearity [F16]
- **Limitations:** Reference-year age is constant across sale years

## Correlated / redundant features
- **Problem Identified:** Correlated pairs and exact sums (GrLivArea, TotalBsmtSF and their parts) make coefficients and SHAP credit arbitrary
- **Methods Considered:** Keep all; keep one of each pair; keep totals not parts; also drop TotalSF
- **Selected Method:** Remove 12 columns (REDUNDANT): the weaker member of each pair, the parts of GrLivArea, TotalBsmtSF and TotalBathrooms, and TotalSF
- **Justification:** Matrix rank deficiency removed (rank 27 of 30 -> 18 of 18); Ridge RMSE change -0.00010 (SE 0.00158)
- **Evidence:** EDA F16: r = 0.88, 0.83, 0.82; exact sums with infinite VIF
- **Limitations:** No accuracy gain was measured; the benefit is interpretability. The weaker member of a pair is chosen by correlation with price

## Leakage prevention
- **Problem Identified:** Fitted statistics must not see validation rows
- **Methods Considered:** Preprocess before splitting; preprocess inside folds
- **Selected Method:** Everything is a Pipeline step, refitted in every fold
- **Justification:** 10 of 10 leakage checks pass (section 16)
- **Evidence:** Sale-context cost +0.0008 RMSE on boosting probe [F22]
- **Limitations:** Checks cover the implemented steps; later model steps need their own review
